`categories.json` marks these inputs `owner_keeps`. The Scope table's rows for them say "whatever a run returns", and `check` requires the two to match. Where no run verifies one, the effective selection keeps it as the owner's, and the pages state each check no run confirmed as not known.

**`session.py`**
- **The fallback in `effective_selection`:** for each `owner_keeps` input where no run kept a part that starts with the input's number:
  - the function keeps the input's `orderable` number, or the input itself, with run `owner`;
  - `owner_fixed` names the run that last decided the function (empty when no run named it), the part that run kept or did not requalify, and each ledger reading of the runs read that did not verify the input, in that category and function;
  - a ledger part that names the input in a longer name, as the pack's product name does, counts as a reading of it.
- **The gates:**
  - `open_selections` counts no owner entry open.
  - `refuted_for_itself` skips owner entries. The refutation stays in `owner_fixed`.
  - `t6_open` counts an owner part as selected. No run verifies the part, so a conflict that names it passes T6 only through `--accept-open`.
- **What each run was given:** `prepare` passes the owner entries as `owner_fixed` and prints each one in the gated categories with the readings that did not verify it. The run's result carries the list, and `record` refuses an output whose list differs from the prepared one. `t6_open` builds the last check's selection from the list that check recorded, so an owner part the check was not given counts as a change. The stale-selection gate rebuilds the upstream parts a run saw the same way (`upstream_view`). The stale-selection gate reads a run recorded without the list under today's list. The runs that decide R5 to R8 now, FU-2F and FU-2G, read plans whose Scope table names R11's owner inputs. A run whose plan predates those rows fails the specification comparison anyway. `t6_open` reads a check recorded without the list, such as T5, as given none.
- **`record`:** rewrites `selection.json` after any run that is not stopped, whenever the effective selection differs from the committed file (`selection_to_write`).
- **`check`:**
  - `fixed_input_fails` holds the fixed-input rules: the Scope table's rows, `owner_keeps` on exactly the rows that say "whatever a run returns", and an `orderable` that starts with its part.
  - `owner_selftest` runs on a throwaway repository. It covers the fallback, the ledger filters, an owner input a run verified, a non-kept input, `owner_items`, `open_selections`, `refuted_for_itself`, `t6_open` (selected parts, and its comparison by the check's list or by none), `upstream_view`, `stale_selections` (a run's list, an empty list, none), `owner_fixed_of`, `differs_from_prepared`, `fixed_input_fails` and `selection_to_write`.
